""" Option 1: Validation only in __init__() - """

class Task:
    def __init__(self, description, status="pending"):
        if description.strip() == "":
            raise ValueError("Description cannot be empty")

        if status not in ("pending", "completed"):
            raise ValueError("Invalid status")

        self.description = description
        self.status = status

class Task:

        if description.strip() == "":
            raise ValueError("Description cannot be empty")

        if status not in ("pending", "completed"):
            raise ValueError("Invalid status")

        self.description = description
        self.status = status


Validation should primarily live in Task.__init__() because the class should guarantee that 
every Task object is valid. This keeps the rules in one place and prevents invalid tasks from 
being created anywhere in the program. User-facing functions such as add_task() may also perform 
validation to provide friendly error messages before attempting to create the object. 
The trade-off is a small amount of duplicated logic, but the program becomes safer and easier to maintain. 
Encapsulation - the object is responsible for protecting its own state.
